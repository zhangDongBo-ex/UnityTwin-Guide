03

Windows 一键包使用

适合直接下载测试，无需自行配置 MySQL 或安装开发工具。

  1. 下载并完整解压

    在 UnityTwin Releases 找到完整联调包。解压到可写目录，例如 C:/Games/UnityTwin；不要在压缩软件中直接运行，也不要只复制 EXE。

  2. 双击 Start.cmd

    首次初始化包内独立数据库，然后启动服务端与可见客户端。后续启动复用 Data/Local，不会覆盖玩家数据。

  3. 登录或注册

    演示账号为 demo，随机密码显示在启动窗口，并保存在 Data/Local/Demo-account.txt。初始有 1000 元宝、10 金币及可领取奖励。新注册角色遵循服务端默认规则，不会自动获得演示账号余额。

  4. 验证兑换与领奖

    在“兑换”购买商品，查看元宝减少、背包增加；在“奖励”和“每日奖励”领取，刷新或重新登录后确认状态与余额一致。

  5. 正常退出并保留数据

    关闭客户端，或双击 Stop.cmd，配套服务端和 MySQL 随后关闭。升级前先停止程序，再备份完整 Data 文件夹。

执行整包自检

先关闭正常客户端，再双击 Verify.cmd。它会在新的 Data/Verify-* 中创建隔离数据库，执行客户端联调，并独立查询数据库核对结果。

结果位置记录在 Data/last-verify.json，包括日志、结果 JSON 和画面截图。正常玩家数据 Data/Local 不参与自检。

数据与日志在哪里

  • Data/Local/mysql：数据库数据。
  • Data/Local/Logs：客户端、服务端、MySQL 日志。
  • BuildInfo.json：源码提交与实际 Runtime 版本。
  • Data 含玩家数据与本机凭据，备份留在本地，不随整包分发。
整包运行范围
Windows 10/11 x64，本机开发联调。已有实机验证以 Windows 11 x64 为基线。当前源码构建包含 .NET / ASP.NET Core 10；早期 Release 不会随源码升级自动更新。已发布客户端的玩法内容也以该包对应提交为准。
04

服务端：从源码启动

先准备数据库与本机配置，再构建并在输出目录运行。

1. 准备一个独立开发数据库

简单本机联调可让 connAuthUserStr 和 connGameDataStr 指向同一个专用数据库，例如 unitytwin_dev；现有回归也使用这一方式。自行准备 MySQL 账号并授予该库所需权限。

原 SQL 文件为 CSharpGameServer/CSharpGameServer/sql/ugame_10001.sql，其中还含历史数据。对新建的空开发库，只提取并执行以下七张表的结构，不直接导入历史账号和记录。

表名用途
account / player账号与玩家角色 / 余额
gamegoods背包物品
bonues / loginbonues普通奖励 / 每日奖励
gametask / mailmessage任务 / 邮件
展开：仅导出七张表结构的命令
PowerShell 7 · 在仓库根目录执行
$schemaText = Get-Content 'CSharpGameServer/CSharpGameServer/sql/ugame_10001.sql' -Raw
$tables = [regex]::Matches($schemaText, 'CREATE TABLE IF NOT EXISTS `\w+` \(.*?\) ENGINE=InnoDB[^;]*;', 'Singleline')
if ($tables.Count -ne 7) { throw '应匹配到七张 InnoDB 表；请检查源 SQL。' }
New-Item -ItemType Directory -Force '.tools/manual' | Out-Null
$tables.Value -join "`n" | Set-Content '.tools/manual/schema-only.sql' -Encoding utf8NoBOM

在 MySQL 管理工具中创建空库 unitytwin_dev，切换到该库后执行生成的 .tools/manual/schema-only.sql。此步骤用于新库初始化，不是旧库迁移脚本。已有数据请先备份。

2. 创建本机配置

PowerShell 7 · 在仓库根目录执行
$serverProject = 'CSharpGameServer/CSharpGameServer/GameServer'
if (!(Test-Path "$serverProject/App.local.config")) {
    Copy-Item "$serverProject/App.config" "$serverProject/App.local.config"
}

在 GameServer/App.local.config 中按下表填写。文件已被 Git 忽略；不要把真实密码写回仓库中的 App.config。

配置项本机单进程联调值说明
GatewayModefalse使用当前单进程入口。
AsServertrue保留主游戏服角色。
AsGateway / AsAuthServer / OnlyHttpServerZonefalse保持模板的本地单服设置。
useRedisfalse模板为 true；本地不使用 Redis 时明确关闭。
BindAddress127.0.0.1在 appSettings 添加此项，将本机开发服务限制在回环地址；模板未设置。
port / wsPort / httpPort6080 / 6082 / 6090修改 TCP 端口后也要修改客户端 port。
HttpAuthAndPlayerWebsitehttp://127.0.0.1:6090/与 HTTP 端口一致。
connAuthUserStr / connGameDataStr填写自己的 MySQL 地址、端口、库、账号、密码本机可指向同一独立库；模板 3306、auth_10001 / ugame_10001 不是已初始化环境。
XML · 添加到已有 appSettings 节点
<add key="BindAddress" value="127.0.0.1" />

连接字符串格式示例：Database=unitytwin_dev;Data Source=127.0.0.1;Port=3306;User Id=你的数据库账号;Password=你的本机密码;Charset=utf8。XML 属性中的特殊字符需要转义，例如 & 写成 &amp;。

3. 构建并启动

PowerShell 7 · 在仓库根目录执行
. ./Tests/Common.ps1
Initialize-TestEnvironment
dotnet build CSharpGameServer/CSharpGameServer/GameServer.sln
if ($LASTEXITCODE -ne 0) { throw '服务端构建失败，请先处理错误。' }
Push-Location CSharpGameServer/CSharpGameServer/GameServer/bin/Debug/net10.0
try { dotnet ./GameServer.dll } finally { Pop-Location }
运行目录与退出方式
服务端按当前工作目录读取 nlog.config 与 Configs/Csvs，所以上面的命令先进入输出目录。构建会优先使用 App.local.config 并产生 GameServer.dll.config。服务启动后保持终端打开；在该终端按 Enter 会进入正常 Shutdown。改配置后要重新构建并重启。

4. 在另一个终端确认就绪

PowerShell 7 · 在仓库根目录执行
Test-NetConnection 127.0.0.1 -Port 6080
Invoke-RestMethod 'http://127.0.0.1:6090/PullingServerDirectConnConfig'

TCP 检查应成功，HTTP 应返回包含 servers 的配置对象。然后运行 Unity 客户端。NLog 文件位于服务端输出目录的 Logs/<日期>。HTTP 就绪只代表服务入口可用，兑换与奖励仍需客户端和数据库回归确认。

Rider 出现代码红线时
已有排查记录显示 Rider 2025.1.2 后端报 Unknown tools version: 18.6，而命令行构建成功。先核对 Rider 对当前 .NET SDK 的支持，再在 Toolset and Build 中选择匹配的 dotnet / MSBuild。详见 .NET 10 开发环境说明；该 IDE 升级不属于本次文档工作。
05

客户端：打开、登录与进入玩法

主工程是 UnityClient；启动场景是 Boot。

  1. 在 Unity Hub 添加 UnityClient

    使用 6000.3.21f1，等待依赖还原与资源导入。首次导入需要网络与时间，先确认 Console 没有编译错误。

  2. 打开启动场景

    Assets/UnityGameFramework/Boot.unity。先启动服务端，再进入 Play Mode。

  3. 核对连接配置

    路径为 Assets/GameMain/Resources/ServerConnection.json；也可从菜单 Game → 服务端接入 → 打开服务端连接配置 打开。

JSON · 当前仓库默认配置
{
  "host": "127.0.0.1",
  "port": 6080,
  "machineId": 0,
  "defaultCharacterId": 10001
}

配置文件只存地址与路由信息。单进程服务端保持 machineId=0；原多进程网关的可选 legacyGatewayRouting=true 属于独立部署配置，不是本机联调必填项。源码中修改地址后重新运行；已打包 EXE 需要重新构建资源与客户端，不能通过修改仓库文件改变旧包。

账号与经济界面

  • 选择“登录 / 注册”，无角色时按现有逻辑创建角色。仅记住账号名，不保存密码。
  • “兑换”：按服务端配置价格购买，完成后刷新角色、奖励和背包。
  • “奖励 / 每日奖励”：查看领取状态；同一奖励重复领取应被拒绝。
  • “背包”：查看道具；“任务 / 邮件”当前主界面为列表查询，任务奖励按服务端完成规则发放。
  • 经济操作超时会断开，不自动重发；重新登录后先核对结果。

进入原联网玩法

登录并有角色后，在 FGUI 主界面点击 “进入玩法”。沿用原场景、UGUI 与逻辑，退出后返回 FGUI 经济界面，并复用同一账号和连接。

房间玩法需要两个账号 / 会话。一个 Unity 工程不能同时被两个编辑器独占打开；使用独立客户端实例或独立工程副本进行多人测试。

07

兑换与奖励：如何确认结果正确

既看客户端反馈，也看持久化后的余额、库存与领取状态。

场景正确行为验证动作
正常兑换扣款与物品写入一起提交；提交后更新在线状态。记录操作前后元宝与道具数，重新登录再次核对。
余额不足 / 写入失败返回失败；扣款和物品增量均不应留下。余额不足可手测；数据库故障注入由真实 MySQL 回归覆盖。
普通 / 每日奖励重复领取同一领取状态只允许一次发放；重复请求被拒绝。领取后重复点击或重新登录检查，不应再次增长。
任务完成任务状态、进度与奖励同事务提交，旧请求不能再次发奖。通过任务回归验证状态重放和异常重试；主界面仅展示列表。
“操作已成功，但数据刷新失败”写操作已成功，后续查询失败。重新刷新或登录查询；不要直接再购买一次。
网络超时 / 断开客户端不自动重发写请求；结果需重新查询。核对持久化状态，无法确认时保留日志进一步检查。
重复领奖与重复购买是两种语义
同一奖励具有领取状态，重复请求不能重复发奖。兑换是购买行为，当前协议没有订单级幂等键：两个合法购买请求可以分别扣款并发货。客户端防连点不能替代服务端订单幂等；超时后不要盲目重发购买。

源码定位：兑换 GameServer/src/Game/Core/GM_Trading/Rules/ExchangeTradingRules.cs；奖励事务 GameServer/src/Game/Core/GM_Bonues/RewardTransaction.cs；客户端会话 UnityClient/Assets/GameMain/Scripts/HotFix/GameLogic/Features/Server/EconomySession.cs。

08

构建 Windows 客户端与完整联调包

FGUI 发布与同步、Luban 导表完成后，再进入构建。

  • Unity 6000.3.21f1 + 同版本 Windows Build Support (IL2CPP)。
  • C++ 工具链：现有验证使用 VS 2019 14.29；需桌面 C++ x64 库和 Windows SDK 10.0.19041.0 或更新版本。
  • 关闭当前工程的 Unity 编辑器后再批处理；如需继续编辑，使用独立工作副本并保留 .meta。
  • 首次 HybridCLR 安装需要网络。构建会依次处理热更新、AOT 元数据、YooAsset 与 IL2CPP。

A. 构建并验收客户端

PowerShell 7 · 在仓库根目录执行
pwsh -File Tests/ClientIntegration/Build-Windows.ps1 -UnityEditor "C:/Unity/6000.3.21f1/Editor/Unity.exe"
pwsh -File Tests/ClientIntegration/Run-Windows.ps1
pwsh -File Tests/ClientIntegration/Package-Windows.ps1

默认 EXE：UnityClient/Builds/Windows/UnityTwin/UnityTwin.exe。Package-Windows 生成客户端 ZIP 与 SHA256；分发时保留整个运行目录。当前脚本构建 Windows x64 IL2CPP Development 客户端，保留调试面板 / 水印。

B. 构建完整联调包

10

常见问题

按报错所在层定位：编辑器 → 运行时 → 连接 → 数据库 → 资源。

客户端连接失败 / 一直登录不了

先确认服务端已启动，执行 TCP / HTTP 就绪检查；核对 ServerConnection.json 的 host、port 与 App.local.config。检查是否把自动化测试的 16680 当成普通连接的 6080。一键包先看启动窗口与 Data/Local/Logs。

服务端提示缺少 Microsoft.AspNetCore.App

GameServer 当前依赖 .NET / ASP.NET Core 10 两套共享框架。用 Tests/Setup-Tools.ps1 准备 SDK，或使用包含对应运行时的新版完整包。不要把 .NET 10 服务端放入旧 .NET 5 Runtime 目录。

Rider 有红线，dotnet build 却通过

检查 Rider 的项目加载日志及 .NET CLI / MSBuild 配置。已有问题为旧 Rider 不识别 MSBuild 18.6；按 NET10-README 升级到支持当前 SDK 的版本。不要为消除 IDE 提示回退业务目标框架。

MySQL 连接失败 / 表不存在

核对数据库端口、库名、账号、权限与七张表是否建立；两条连接字符串都要填写。模板密码为空，不能直接当成可用开发环境。不要用删除 Data 的方式排错。

找不到 nlog.config 或 CSV

从构建输出目录启动 GameServer.dll，并确认 Configs 与 nlog.config 已复制。只从任意目录执行 DLL 可能导致相对路径解析失败。

FGUI 显示旧界面 / 提示缺包

在 Game 与 Launch 源工程完整发布，确认唯一目录 output/res/Publish 与 output_launch/res/Publish，再运行 Sync-Client.ps1。核对控件名称；旧分发包需要重新构建，不能只修改源工程。

Unity 批处理提示工程已被打开

保存工作并关闭该工程的编辑器，或使用独立副本 / worktree 批处理。不要直接结束未保存窗口；复制资源时保留 .meta。

IL2CPP / HybridCLR 构建失败

核对 Unity 版本、Windows IL2CPP 模块、桌面 C++ x64 与 Windows SDK。查看 windows-InstallHybridCLR.log / windows-Build.log 中第一个错误；热更新编译成功不能替代完整 Player 构建成功。

领取显示已领 / 新账号没有奖励

先看当前角色与服务器领取状态。首次登录每日记录遵循原 days=0 规则，不能默认新角色必有演示奖励。需要稳定复现兑换和领奖时，使用一键包 demo 或 Verify 的明确测试数据。

操作超时，是否直接再点一次

先重新登录查询余额、背包和领取状态。购买请求没有订单幂等键，重复发起可能是第二笔有效购买；“操作已成功，但数据刷新失败”也不应通过再次购买来刷新。

端口被占用 / 一键包启动失败

先停止自己已启动的联调实例。Start.cmd 不会终止占用端口的其他程序。确认 6080 / 6082 / 6090 / 13316 空闲；检查 mysql-init-error.log、mysql-console-error.log、query-error.log、server-error.log。

在哪里看原 Game 内容 / XPHero 地图

原联网源码完整保存于 LegacyNetworkClient，迁入逻辑位于 Features/LegacyGameplay，资源位于 AssetRaw/LegacyGameplay。XPHero 已备份移除；原 RVO 世界与独立 RVOMapEditor 仍保留。
